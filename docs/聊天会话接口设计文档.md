## 1. 概述

### 1.1 目标

基于已有的 **DeepSeek 聊天模型**（`spring-ai-starter-model-deepseek`）和已在 `schema.sql` 中定义的 **`chat_session`**（会话表）、**`chat_message`**（消息表），实现一套完整的聊天会话 REST 接口，覆盖：

- 会话的创建、查询、重命名、删除
- 消息的**同步发送**与**SSE 流式发送**（逐 token 推送，体验更佳），历史消息查询
- 多轮对话上下文管理（从数据库加载历史消息组装 Prompt）

### 2.2 分层设计

遵循项目已有的 **Entity → Mapper → Service → Controller** 四层结构，与 `SysUser` 模块保持一致：

- **Entity**：MyBatis-Plus 实体类，注解映射表结构
- **Mapper**：继承 `BaseMapper<T>`，基础 CRUD 免费，无需 XML
- **Service**：接口继承 `IService<T>`，实现继承 `ServiceImpl<Mapper, T>`
- **Controller**：`@RestController` + `@RequestMapping("/chat")`，普通接口返回 `Result<T>`，流式接口返回 `SseEmitter`
- **DTO**：请求入参（带校验注解）、响应视图对象（带 Swagger 注解）、SSE 事件对象

### 2.3 同步 vs 流式对比

| 维度 | 同步 `POST /chat/send` | 流式 `GET /chat/stream` |
|------|----------------------|------------------------|
| 客户端体验 | 等待完整回复，有"转圈圈"停顿感 | 逐 token 打字机效果，响应时延低 |
| 协议 | HTTP POST + JSON 响应 | HTTP GET + SSE (text/event-stream) |
| Spring AI API | `ChatModel.call(Prompt)` | `StreamingChatModel.stream(Prompt)` |
| Controller 返回 | `Result<ChatMessageVO>` | `SseEmitter` |
| 消息入库 | 调用完成后一次性保存用户+AI消息 | 用户消息立即入库，AI 消息流结束后拼接完整 content 入库 |
| 异常处理 | 抛 BusinessException → 全局异常处理器 | 通过 `SseEmitter.completeWithError()` 发送错误事件 |
| 适用场景 | 简单测试、服务端调用、后端集成 | 前端聊天 UI、追求响应速度 |

## 3. 接口设计

### 3.1 会话管理接口

#### 3.1.1 创建会话

- **URL**：`POST /chat/session/create`
- **请求体**：

```json
{
  "userId": 1,
  "title": "新会话",
  "sessionType": "normal"
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| userId | Long | 是 | — | 用户 ID |
| title | String | 否 | "新会话" | 会话标题 |
| sessionType | String | 否 | "normal" | 会话类型 |

- **响应**：`Result<ChatSessionVO>`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "userId": 1,
    "title": "新会话",
    "sessionType": "normal",
    "modelName": "deepseek-v4-flash",
    "createTime": "2026-08-08T10:00:00",
    "updateTime": "2026-08-08T10:00:00"
  }
}
```

- **业务逻辑**：
  1. 生成 UUID 作为业务 `sessionId`
  2. `modelName` 默认读取配置 `spring.ai.deepseek.chat.options.model`
  3. 入库并返回

#### 3.1.2 会话列表

- **URL**：`GET /chat/session/list?userId=1`
- **参数**：`userId`（Long，必填）
- **响应**：`Result<List<ChatSessionVO>>` — 按 updateTime 倒序

#### 3.1.3 会话详情

- **URL**：`GET /chat/session/{sessionId}`
- **路径参数**：`sessionId`（业务会话 ID，String）
- **响应**：`Result<ChatSessionVO>`
- **异常**：会话不存在抛出 `BusinessException(NOT_FOUND)`

#### 3.1.4 重命名会话

- **URL**：`POST /chat/session/rename`
- **请求体**：

```json
{
  "sessionId": "a1b2c3d4-e5f6-...",
  "title": "关于Spring AI的讨论"
}
```

- **响应**：`Result<Void>`

#### 3.1.5 删除会话

- **URL**：`POST /chat/session/delete`
- **请求体**：

```json
{
  "sessionId": "a1b2c3d4-e5f6-..."
}
```

- **响应**：`Result<Void>`
- **说明**：逻辑删除（`is_deleted=1`），本期仅删除会话本身，级联消息删除留待后续迭代。

### 3.2 消息接口

#### 3.2.1 发送消息（同步）

- **URL**：`POST /chat/send`
- **Content-Type**：`application/json`
- **请求体**：

```json
{
  "sessionId": "a1b2c3d4-e5f6-...",
  "userId": 1,
  "content": "你好，介绍一下Spring AI",
  "systemPrompt": "你是一个有帮助的AI助手。"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sessionId | String | 是 | 业务会话 ID |
| userId | Long | 是 | 用户 ID（鉴权用） |
| content | String | 是 | 消息内容（最大 10000 字） |
| systemPrompt | String | 否 | 自定义系统提示词 |

- **响应**：`Result<ChatMessageVO>`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "messageId": 42,
    "sessionId": "a1b2c3d4-e5f6-...",
    "role": "assistant",
    "content": "Spring AI 是 Spring 官方推出的 AI 应用开发框架……",
    "modelName": "deepseek-v4-flash",
    "finishReason": "stop",
    "messageIndex": 3,
    "createTime": "2026-08-08T10:01:23"
  }
}
```

- **核心流程**：

```
1. 参数校验（sessionId、userId、content 非空）
2. 根据业务 sessionId 查 ChatSession，不存在则抛异常
3. 校验 session.userId == userId（防止越权）
4. 查询该会话当前最大 message_index
5. 构建用户消息 ChatMessage（role=user, index=max+1），入库
6. 查询该会话所有未删除历史消息，按 message_index 升序
7. 组装 Spring AI Prompt（system + history + current user message）
8. 调用 chatModel.call(prompt) 获取完整 AI 回复
9. 构建 AI 回复消息 ChatMessage（role=assistant, index=max+2），入库
10. 首轮对话自动设置标题（截取用户消息前20字）
11. 返回 AI 回复 VO
```

#### 3.2.2 发送消息（SSE 流式）★ 新增

- **URL**：`GET /chat/stream`
- **Content-Type**：产生 `text/event-stream`
- **请求参数**（Query 参数，SSE 惯例用 GET 以便 EventSource 直接连接）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sessionId | String | 是 | 业务会话 ID |
| userId | Long | 是 | 用户 ID |
| content | String | 是 | 消息内容（URL 编码） |
| systemPrompt | String | 否 | 自定义系统提示词 |

> 💡 **为什么用 GET 而非 POST？** 浏览器原生 `EventSource` API 只支持 GET；如果前端使用 `fetch` + `ReadableStream` 则 POST 也可以。为了最大兼容性，默认使用 GET。后端也可额外提供 POST 版本（见"后续迭代"）。

- **响应**：SSE 事件流，逐事件推送。事件类型分 4 种：

| event | 触发时机 | data 结构 |
|-------|---------|-----------|
| `start` | 流开始（连接建立、用户消息入库完成） | `{"messageId": 43, "sessionId": "...", "index": 2}` |
| `message` | 每个 token 片段到达时（可能推几十到几百次） | `{"content": "Spring", "index": 0}` → `{"content": " AI", "index": 1}` …… |
| `done` | AI 回复完成，完整消息已入库 | `{"messageId": 44, "content": "完整回复...", "finishReason": "stop", "index": 3}` |
| `error` | 流式过程中出错 | `{"code": 5001, "message": "AI 流式响应异常: xxx"}` |

- **SSE 原始报文示例**：

```
event: start
data: {"messageId":43,"sessionId":"a1b2c3d4-...","index":2}

event: message
data: {"content":"Spring","index":0}

event: message
data: {"content":" AI","index":1}

event: message
data: {"content":" 是","index":2}

...（更多 token 片段）...

event: done
data: {"messageId":44,"content":"Spring AI 是 Spring 官方推出的 AI 应用开发框架……","finishReason":"stop","index":3}

```

- **前端 EventSource 调用示例**：

```javascript
const params = new URLSearchParams({
  sessionId: 'a1b2c3d4-...',
  userId: '1',
  content: '你好，介绍一下Spring AI'
});

const es = new EventSource(`/chat/stream?${params}`);

es.addEventListener('start', (e) => {
  const data = JSON.parse(e.data);
  console.log('开始接收，用户消息ID:', data.messageId);
});

es.addEventListener('message', (e) => {
  const data = JSON.parse(e.data);
  // 将 data.content 追加到聊天窗口
  appendToChat(data.content);
});

es.addEventListener('done', (e) => {
  const data = JSON.parse(e.data);
  console.log('完整回复已入库，消息ID:', data.messageId);
  es.close();
});

es.addEventListener('error', (e) => {
  const data = JSON.parse(e.data);
  console.error('流式错误:', data.message);
  es.close();
});

// ⚠️ EventSource 默认 error 事件（网络错误等）
es.onerror = () => {
  console.error('连接异常');
  es.close();
};
```

- **核心流程**：

```
1. 参数校验（sessionId、userId、content 非空）
2. 根据业务 sessionId 查 ChatSession，校验归属权
3. 查询该会话当前最大 message_index
4.【同步部分·立即执行】
   - 保存用户消息 ChatMessage（role=user, index=max+1）
   - 首轮自动生成标题
   - 创建 SseEmitter（超时 120s）
   - 发送 "start" 事件（包含用户消息ID）
5.【异步部分·在线程池中执行】
   a. 加载历史消息，组装 Prompt（同同步流程）
   b. 调用 streamingChatModel.stream(prompt) 获取 Flux<ChatResponse>
   c. 订阅 Flux：
      - onNext：从 ChatResponse 中取出 token 片段，通过 emitter.send() 发 "message" 事件
               同时用 StringBuilder 拼接完整内容
      - onError：发 "error" 事件，emitter.completeWithError()，记录日志
               （注意：用户消息已入库但 AI 回复不入库，用户可重试）
      - onComplete：
          · 构建 AI 回复消息 ChatMessage（role=assistant, index=max+2），
            content = StringBuilder 完整内容，finishReason = 最后一个片段的 finishReason
          · 入库
          · 发送 "done" 事件（包含完整消息信息）
          · emitter.complete()
6. 立即返回 SseEmitter 给 Servlet 容器（异步响应开始）
```

- **SseEmitter 关键配置**：
  - 超时时间：**120 秒**（覆盖长回复场景；Spring AI DeepSeek 流式调用通常 10-60s）
  - 超时回调：发送 `error` 事件并 `complete()`
  - 异常回调：记录日志，确保连接关闭
  - 使用 `AsyncConfig` 中已有线程池或新建专用 `chatStreamExecutor` 线程池（core=4, max=8, queue=50），避免阻塞 Tomcat 请求线程

#### 3.2.3 查询消息列表

- **URL**：`GET /chat/messages?sessionId=xxx&userId=1`
- **参数**：`sessionId`（必填）、`userId`（必填，鉴权）
- **响应**：`Result<List<ChatMessageVO>>` — 按 messageIndex 升序

**ChatServiceImpl.sendStream() 流式流程伪代码**★ 新增：

```java
public SseEmitter sendStream(String sessionId, Long userId, String content, String systemPrompt) {
    // 1. 校验 & 准备
    ChatSession session = chatSessionService.getBySessionId(sessionId);
    if (session == null) throw new BusinessException(ResultCode.NOT_FOUND, "会话不存在");
    if (!session.getUserId().equals(userId))
        throw new BusinessException(ResultCode.FORBIDDEN, "无权访问该会话");

    // 2. 查最新消息 index
    Integer maxIdx = findMaxMessageIndex(session.getId());
    int userIdx = (maxIdx == null) ? 0 : maxIdx + 1;
    int aiIdx   = userIdx + 1;

    // 3. 立即保存用户消息（不能在异步线程里做，因为 SseEmitter 要先发 start 事件告知用户消息ID）
    ChatMessage userMsg = buildUserMessage(session.getId(), userId, content, userIdx);
    chatMessageMapper.insert(userMsg);

    // 4. 首轮自动标题
    if ("新会话".equals(session.getTitle()) && userIdx == 0) {
        session.setTitle(content.length() > 20 ? content.substring(0, 20) + "..." : content);
        chatSessionService.updateById(session);
    }

    // 5. 加载历史（包含刚插入的用户消息）
    List<ChatMessage> history = loadHistoryMessages(session.getId());
    List<Message> promptMessages = buildPromptMessages(history, systemPrompt);

    // 6. 创建 SseEmitter（超时 120s）
    SseEmitter emitter = new SseEmitter(120_000L);

    // 超时/异常处理
    emitter.onTimeout(() -> {
        try {
            emitter.send(SseEmitter.event().name("error")
                .data(ChatStreamEvent.error(ResultCode.AI_STREAM_ERROR.getCode(), "响应超时")));
        } catch (IOException ignored) {}
        emitter.complete();
    });
    emitter.onError(e -> log.error("SSE 连接异常", e));

    // 7. 异步线程中执行流式调用（立即返回 emitter 给容器）
    chatStreamExecutor.execute(() -> {
        StringBuilder fullContent = new StringBuilder();
        int[] tokenIndex = {0};
        try {
            // 7.1 发送 start 事件
            emitter.send(SseEmitter.event().name("start")
                .data(ChatStreamEvent.start(sessionId, userMsg.getId(), userIdx)));

            // 7.2 调用 StreamingChatModel
            Flux<ChatResponse> flux = streamingChatModel.stream(new Prompt(promptMessages));
            String[] finishReason = {null};

            flux.doOnError(e -> {
                  log.error("DeepSeek 流式调用失败", e);
                  ChatStreamEvent err = ChatStreamEvent.error(
                      ResultCode.AI_STREAM_ERROR.getCode(), "AI 调用失败: " + e.getMessage());
                  emitter.send(SseEmitter.event().name("error").data(err));
                  emitter.completeWithError(e);
              })
              .doOnComplete(() -> {
                  // 7.3 流结束后保存 AI 回复消息
                  ChatMessage aiMsg = buildAiMessage(session.getId(), userId,
                      fullContent.toString(), aiIdx, session.getModelName(), finishReason[0]);
                  chatMessageMapper.insert(aiMsg);

                  // 7.4 发送 done 事件
                  emitter.send(SseEmitter.event().name("done")
                      .data(ChatStreamEvent.done(sessionId, aiMsg.getId(),
                          fullContent.toString(), finishReason[0], session.getModelName(), aiIdx)));
                  emitter.complete();
              })
              .subscribe(chunk -> {
                  String token = chunk.getResult().getOutput().getText();
                  if (token != null) {
                      fullContent.append(token);
                      // 7.5 逐 token 发送 message 事件
                      emitter.send(SseEmitter.event().name("message")
                          .data(ChatStreamEvent.message(token, tokenIndex[0]++)));
                  }
                  // 记录 finishReason（最后一个 chunk 会携带）
                  if (chunk.getResult().getMetadata() != null
                      && chunk.getResult().getMetadata().getFinishReason() != null) {
                      finishReason[0] = chunk.getResult().getMetadata().getFinishReason();
                  }
              });

        } catch (Exception e) {
            log.error("SSE 流式处理异常", e);
            try {
                emitter.send(SseEmitter.event().name("error")
                    .data(ChatStreamEvent.error(ResultCode.AI_STREAM_ERROR.getCode(), e.getMessage())));
            } catch (IOException ignored) {}
            emitter.completeWithError(e);
        }
    });

    return emitter;
}
```

## 8. 注意事项

1. **sessionId 双字段问题**：`chat_message.session_id` 是 bigint，存 `chat_session.id`（数据库主键）；而对外暴露的是 `chat_session.session_id`（varchar(64) UUID）。Service 层要做一次「业务 sessionId → 数据库主键 id」的转换。
2. **消息序号 messageIndex**：单会话内维护连续递增的 `message_index`，发送时先查 `MAX(message_index)` 再 +1。
3. **同步接口事务**：`send()` 方法加 `@Transactional`，保证用户消息和 AI 回复同时成功/失败。
4. **流式接口不能用 `@Transactional`**：流式发送是「先同步保存用户消息 → 异步线程调 AI → 异步保存 AI 消息」，无法在一个事务里完成。设计为：用户消息入库成功即返回 emitter；AI 调用失败则用户消息保留（方便重试），AI 消息不入库，通过 error 事件通知前端。
5. **SSE 超时处理**：设置 120s 超时；超时/网络断开时发送 error 事件并 complete。前端应监听 error 事件做重试或提示。
6. **SSE 异常隔离**：`sendStream()` 里的校验（会话不存在、越权）在同步阶段抛出，走 GlobalExceptionHandler；但在异步 Flux 订阅阶段（onNext/onError/onComplete），所有 IO 异常都要 try-catch，不能让异常逃逸出异步线程，否则 Tomcat 异步请求会被异常中断导致前端收到不完整响应。
7. **中文参数 URL 编码**：`/chat/stream` 使用 GET 时，`content` 参数中的中文/特殊字符前端必须用 `encodeURIComponent` 编码，后端 Spring MVC 会自动解码。
8. **上下文长度**：本期加载全部历史消息，过长对话可能超出 token 限制。后续迭代加滑动窗口/摘要压缩。
9. **线程池隔离**：流式接口使用独立线程池 `chatStreamExecutor`，不与已有 `documentProcessExecutor`（文档处理）混用，避免大文件上传/向量化影响聊天响应速度。
10. **`StreamingChatModel` Bean 注入**：Spring AI DeepSeek Starter 默认自动装配 `StreamingChatModel`，直接 `@Resource` 或 `@Autowired` 注入即可。若启动时找不到该 Bean，检查 `spring.ai.deepseek.chat.enabled` 是否为 true（默认 true）。
11. **Nginx 反向代理注意**：如部署在 Nginx 后，需配置 `proxy_buffering off;` 和 `proxy_read_timeout 120s;`，否则 Nginx 会缓冲 SSE 响应导致流式效果失效。
