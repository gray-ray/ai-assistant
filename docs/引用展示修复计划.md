# 引用（Citations）展示修复计划

> 问题现象：对话回答中带有 `[1] [2]` 等引用标注，但用户看不到引用的具体内容（来源文档、章节、片段等）。

## 一、问题根因总览

引用数据在后端生成阶段是完整的（由 `ContextAssemblyServiceImpl` 构建），但在 **持久化 → 历史查询 → 前端类型 → 前端 Hook → 前端 UI** 这条链路上有多处断裂，导致用户始终看不到引用详情。

断裂点清单：

| # | 层级 | 位置 | 问题 |
|---|------|------|------|
| 1 | 数据库 | `chat_message` 表 | 没有 citations 字段/表，引用从未落库 |
| 2 | 后端实体 | `ChatMessage.java` | 没有 citations 字段 |
| 3 | 后端 API | `ChatController.listMessages()` | 历史消息 VO 转换时 citations 传 `null` |
| 4 | 前端类型 | `types/chat.ts` | `ChatMessageVO` / `ChatStreamEvent` 无 `citations` 字段 |
| 5 | 前端 Hook | `hooks/useSSE.ts` | `done` 事件未读取 `evt.citations` |
| 6 | 前端 Hook | `hooks/useChatSession.ts` | `DisplayMessage` 无 citations，流式/历史加载均未写入 |
| 7 | 前端 UI | `MessageList.tsx` / `Markdown.tsx` | 没有引用列表和 `[n]` 悬浮/点击交互 |

---

## 二、修复方案选型

### 方案 A：JSON 列存储（推荐）

在 `chat_message` 表加 `citations_json` 字段（JSON 类型），`ChatMessage` 实体加对应字段，MyBatis-Plus 通过 `typeHandler` 自动序列化/反序列化 `List<CitationVO>`。

- **优点**：改动小，一张表搞定，查询简单，引用随消息一起读写
- **缺点**：不支持按文档维度反向查询引用（目前无此需求）
- **适用**：当前业务场景

### 方案 B：独立 `chat_message_citation` 表

新建一张关联表，每条引用一行，通过 `message_id` 外键关联。

- **优点**：范式化，可按文档/章节聚合统计
- **缺点**：读写都要 JOIN / 批量操作，改动量大
- **适用**：未来需要对引用做复杂查询时再考虑

**结论：采用方案 A（JSON 列）。** 若将来有需求再迁移到方案 B。

---

## 三、详细改造步骤

### 阶段 1：后端持久化 & 历史接口（必须）

#### 1.1 数据库 DDL

`src/main/resources/db/schema.sql` 增加：

```sql
-- 消息表增加 citations_json 字段（存储引用来源列表 JSON）
ALTER TABLE chat_message
    ADD COLUMN citations_json JSON NULL COMMENT '引用来源列表 JSON（仅 assistant 消息有值）'
    AFTER content;
```

> 注：项目使用 `if not exists` 风格，实际落地可用 Flyway/Liquibase 增量脚本，或直接在 schema.sql 中 `ADD COLUMN ...` 加 `IF NOT EXISTS` 兼容（MySQL 8.0 不支持 ADD COLUMN IF NOT EXISTS，需用存储过程或在应用启动时判断）。
>
> **建议**：项目当前没有迁移工具，直接在 `schema.sql` 的 `chat_message` 建表语句中补字段，并在 `docs/` 下新增一份 `v2_citations_migration.sql` 供已有库手工执行。

#### 1.2 ChatMessage 实体加字段

文件：`chat/entity/ChatMessage.java`

增加字段 + MyBatis-Plus JSON 类型处理器：

```java
@TableField(typeHandler = JacksonTypeHandler.class)
@Schema(description = "引用来源列表 JSON（仅 assistant 消息有值）")
private List<CitationVO> citations;
```

> 注意：`CitationVO` 目前在 `vo` 包里，实体直接依赖 VO 有点反模式。
>
> 两种做法：
> - 做法 1：将引用的持久化模型抽成 `chat/entity/ChatMessageCitation`（简单 POJO），实体存 `List<ChatMessageCitation>`，Service 层再转 `CitationVO`。
> - 做法 2：图省事，实体直接用 `CitationVO`（小项目可接受）。
>
> **建议：做法 1**，保持分层清晰，新增 `chat/entity/ChatMessageCitation.java`。

#### 1.3 ChatServiceImpl 保存时写入 citations

文件：`chat/service/impl/ChatServiceImpl.java`

- 同步 `send()`：保存 aiMsg 前设置 `aiMsg.setCitations(toEntityCitations(citations))`
- 流式 `sendStream()`：在 `flux.subscribe` 的 `onComplete` 中，保存 aiMsg 前设置 citations

新增辅助方法 `toEntityCitations(List<CitationVO>)` 和反向 `toCitationVOsFromEntity(List<ChatMessageCitation>)`。

#### 1.4 历史消息接口返回 citations

文件：`chat/controller/ChatController.java`

`listMessages()` 中将 `null` 改为从实体读取：

```java
// 修改前
list.stream().map(m -> toMessageVO(m, sessionId, null)).collect(Collectors.toList());

// 修改后
list.stream().map(m -> toMessageVO(m, sessionId, toCitationVOs(m.getCitations())))
    .collect(Collectors.toList());
```

> 在 Controller 或 Service 层做 `ChatMessageCitation` → `CitationVO` 的转换均可，建议放在 Controller 层的 `toMessageVO` 旁。

#### 1.5 Mapper XML 配置 JSON 字段映射

如果项目用 XML mapper，需在 `resultMap` 中加：

```xml
<result property="citations" column="citations_json"
        typeHandler="com.baomidou.mybatisplus.extension.handlers.JacksonTypeHandler"/>
```

> 用 MyBatis-Plus 注解方式的话 `@TableField(typeHandler = ...)` 已足够，但需确认实体类上有 `@TableName(autoResultMap = true)`。

### 阶段 2：前端类型 & 数据流（必须）

#### 2.1 补充 TS 类型

文件：`ai-assistant-frontend/src/types/chat.ts`

新增 `CitationVO` 接口并在相关类型上加字段：

```typescript
export interface CitationVO {
  index: number
  documentId: number
  documentName: string
  chapterTitle?: string
  content: string
  score?: number
}

// ChatMessageVO 增加
export interface ChatMessageVO {
  // ... 现有字段
  citations?: CitationVO[]
}

// ChatStreamEvent 增加
export interface ChatStreamEvent {
  // ... 现有字段
  citations?: CitationVO[]
}
```

#### 2.2 useSSE hook 捕获 citations

文件：`ai-assistant-frontend/src/hooks/useSSE.ts`

改造点：
- 新增 `citations` state + ref（类型 `CitationVO[]`）
- `done` 事件中读取 `evt.citations` 并 set
- `reset()` 清空 citations
- return 对象中暴露 `citations`

```typescript
case 'done':
  if (evt.citations) {
    setCitations(evt.citations)
  }
  // ... 现有逻辑
  break
```

#### 2.3 useChatSession 打通 citations 到 DisplayMessage

文件：`ai-assistant-frontend/src/hooks/useChatSession.ts`

- `DisplayMessage` 接口新增 `citations?: CitationVO[]`
- 历史消息加载（`loadMessages`）时，将 `ChatMessageVO.citations` 映射到 `DisplayMessage`
- 流式结束（SSE done 后），把 `useSSE().citations` 写入最终 assistant 消息

### 阶段 3：前端 UI 展示（必须 + 可选增强）

#### 3.1 消息底部引用列表（必须）

文件：`components/MessageList.tsx` 或新增 `components/CitationList.tsx`

在 assistant 消息底部渲染一个引用来源区：

```
━━━━━━━━━━━━━━━━
引用来源：
[1] 《产品说明书》- 第三章 功能介绍
[2] 《API 文档》- 2.1 接口鉴权
...
```

- 点击某项展开/折叠，显示完整片段内容
- 或 hover 时显示 tooltip（参见 3.2）

#### 3.2 `[n]` 标注悬浮展示（推荐，可选）

文件：`components/Markdown.tsx`

将正文里的 `[1]`、`[2]` 等引用标注渲染为可交互元素：
- 鼠标悬浮 → 弹出 tooltip，显示对应引用的 `documentName + chapterTitle + content`
- 点击 → 滚动到底部引用列表对应位置，或直接展开该引用详情

实现方式：自定义 `react-markdown` 的文本渲染插件，用正则替换 `\[(\d+)\]` 为 `<CitationRef index={n}/>` 组件。

> 注意边界：代码块、行内代码里的 `[1]` 不要替换。

#### 3.3 引用卡片样式（可选）

- 文档图标 + 文档名 + 章节
- 片段内容截断 + "展开全部"
- 相关度分数可视化（星级 / 进度条，可选）

## 五、实施顺序建议

按依赖关系和收益优先级排序：

1. **阶段 1**（后端持久化） — 解决"刷新就丢引用"的核心问题
2. **阶段 2**（前端数据流） — 解决"有数据但拿不到"的问题
3. **阶段 3.1**（底部引用列表） — 解决"用户看不到引用内容"的问题
4. **阶段 3.2**（`[n]` 悬浮） — 体验增强，可分开发版
5. **阶段 3.3**（样式优化） — 视觉优化，优先级最低

建议分 2 个 PR / 提交：
- **PR-1：后端 + 前端数据流**（阶段 1 + 2）
- **PR-2：前端 UI**（阶段 3）

## 七、后续优化方向（本期不做）

1. **引用去重 & 合并**：同一文档多个片段合并展示
2. **跳转到原文**：点击引用打开对应文档的对应章节（需文档预览能力）
3. **引用可点击反馈**：用户点击 `[n]` 时高亮对应引用卡片
4. **引用质量评估**：展示相关性分数，区分"强引用"和"弱引用"
5. **迁移到独立 `chat_message_citation` 表**：支持按文档维度统计引用使用情况
