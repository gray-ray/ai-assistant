## 1. 通用说明

### 1.1 统一返回结构

所有非 SSE 接口统一返回 JSON：

```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | Integer | 状态码，`0` 表示成功，非 0 表示失败 |
| `message` | String | 提示信息，成功时为 `"success"` |
| `data` | Any | 业务数据，失败时为 `null` |

### 1.2 错误码

| code | message | 说明 |
|------|---------|------|
| 0 | success | 成功 |
| 400 | 请求参数错误 | 参数校验失败 |
| 401 | 未授权 | 未登录/Token 无效（目前未启用鉴权） |
| 403 | 禁止访问 | 无权限 |
| 404 | 资源不存在 | 会话/消息不存在 |
| 500 | 系统内部错误 | 服务端异常 |
| 5001 | AI 流式响应异常 | SSE 流中 AI 调用失败 |

### 1.3 跨域

后端已配置全局 CORS（`WebMvcConfig`），允许所有来源、所有方法、所有 Header，前端开发无需配置代理（如配置代理请以代理为准）。

### 1.4 数据类型说明

- **时间字段**（`createTime`、`updateTime`）为 `LocalDateTime`，JSON 序列化格式默认 `yyyy-MM-ddTHH:mm:ss`（如 `"2026-08-08T10:30:00"`），前端需自行格式化展示。
- **`sessionId`**：业务会话 ID，字符串类型（UUID），不是数据库自增主键。所有会话/消息接口以此 ID 作为业务标识。
- **`role`**：消息角色，取值 `user`（用户）/ `assistant`（AI助手）/ `system`（系统提示词）。

## 3. 会话管理接口

### 3.1 创建会话

用户首次聊天前需创建一个会话（或前端自动创建默认会话）。

**请求**

- Method: `POST`
- URL: `/chat/session/create`
- Content-Type: `application/json`

**请求体**

```json
{
  "userId": 1,
  "title": "新会话",
  "sessionType": "normal"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `userId` | Long | **是** | 用户 ID |
| `title` | String | 否 | 会话标题，默认 `"新会话"` |
| `sessionType` | String | 否 | 会话类型，默认 `"normal"` |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "userId": 1,
    "title": "新会话",
    "sessionType": "normal",
    "modelName": "deepseek-v4-flash",
    "createTime": "2026-08-08T10:30:00",
    "updateTime": "2026-08-08T10:30:00"
  }
}
```

**`data` 字段说明（ChatSessionVO）**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 数据库主键 ID |
| `sessionId` | String | **业务会话 ID**（后续所有接口使用此字段） |
| `userId` | Long | 用户 ID |
| `title` | String | 会话标题 |
| `sessionType` | String | 会话类型 |
| `modelName` | String | 使用的 AI 模型名称 |
| `createTime` | String | 创建时间 |
| `updateTime` | String | 更新时间 |

## 4. 消息接口

### 4.1 发送消息（同步）

> ⚠️ 此接口会等待 AI 完整生成回复后一次性返回，用户等待时间较长。**推荐使用 4.2 SSE 流式接口**获得更好的打字机效果体验。

**请求**

- Method: `POST`
- URL: `/chat/send`
- Content-Type: `application/json`

**请求体**

```json
{
  "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "userId": 1,
  "content": "你好，请介绍一下 Spring Boot",
  "systemPrompt": "你是一个专业的Java技术专家"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sessionId` | String | **是** | 业务会话 ID |
| `userId` | Long | **是** | 用户 ID |
| `content` | String | **是** | 消息内容，最大 10000 字 |
| `systemPrompt` | String | 否 | 系统提示词，用于设定 AI 角色/行为 |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "messageId": 2,
    "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "role": "assistant",
    "content": "Spring Boot 是由 Pivotal 团队提供的全新框架...",
    "modelName": "deepseek-v4-flash",
    "finishReason": "stop",
    "messageIndex": 2,
    "createTime": "2026-08-08T10:31:00"
  }
}
```

> **注意**：同步接口返回的是 **AI 回复的消息**（`role: "assistant"`）。用户发送的消息已在服务端保存，可通过消息列表接口查询。

---

### 4.2 发送消息（SSE 流式）⭐ 推荐

基于 Server-Sent Events (SSE) 的流式接口，AI 生成的内容会以增量方式逐段推送到前端，实现打字机效果。

**请求**

- Method: `GET`
- URL: `/chat/stream`
- Content-Type: 不适用（GET 请求，参数通过 Query String 传递）

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sessionId` | String | **是** | 业务会话 ID |
| `userId` | Long | **是** | 用户 ID |
| `content` | String | **是** | 消息内容，最大 10000 字（需 URL 编码） |
| `systemPrompt` | String | 否 | 系统提示词（需 URL 编码） |

**示例**

```
GET /chat/stream?sessionId=a1b2c3d4-e5f6-7890-abcd-ef1234567890&userId=1&content=%E4%BD%A0%E5%A5%BD
```

> ⚠️ **注意**：`content` 和 `systemPrompt` 为中文/特殊字符时，必须使用 `encodeURIComponent` 进行 URL 编码。

#### SSE 事件格式

服务端通过 SSE 推送多个事件，每个事件格式为：

```
data: {"event":"...", ...}

```

每个事件都是一个 JSON 对象，通过 `event` 字段区分类型：

| event 类型 | 数量 | 说明 |
|-----------|------|------|
| `start` | 1 个 | 开始生成，携带用户消息 ID 和序号 |
| `message` | N 个 | 增量文本片段，每次携带一段新的文本 |
| `done` | 1 个 | 生成完成，携带完整内容和元信息 |
| `error` | 0 或 1 个 | 生成出错 |

事件序列保证：`start` → N 个 `message` → `done` 或 `error`。

---

#### 事件详情

**① start 事件**

```json
{
  "event": "start",
  "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "messageId": 1,
  "index": 1,
  "content": null,
  "fullContent": null,
  "finishReason": null,
  "modelName": null,
  "code": null,
  "message": null
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessionId` | String | 业务会话 ID |
| `messageId` | Long | 用户消息 ID（已保存） |
| `index` | Integer | 消息在会话内的序号 |

**前端处理**：将用户消息渲染到聊天界面，显示"AI 正在输入"的加载状态。

---

**② message 事件**

```json
{
  "event": "message",
  "content": "Spring",
  "index": 2
}
```

```json
{
  "event": "message",
  "content": " Boot",
  "index": 2
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `content` | String | 增量文本片段（需要追加拼接） |
| `index` | Integer | 当前 AI 回复消息的序号 |

**前端处理**：将 `content` **追加**到 AI 回复的气泡中，实现打字机效果。

---

**③ done 事件**

```json
{
  "event": "done",
  "sessionId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "messageId": 2,
  "index": 2,
  "content": null,
  "fullContent": "Spring Boot 是由 Pivotal 团队提供的全新框架...",
  "finishReason": "stop",
  "modelName": "deepseek-v4-flash",
  "code": null,
  "message": null
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessionId` | String | 业务会话 ID |
| `messageId` | Long | AI 回复消息 ID（已保存） |
| `index` | Integer | AI 回复消息的序号 |
| `fullContent` | String | AI 回复的**完整**内容 |
| `finishReason` | String | 结束原因：`stop`（正常结束）/ `length`（达到长度限制） |
| `modelName` | String | 使用的模型名称 |

**前端处理**：隐藏加载状态。可用 `fullContent` 做最终内容校验/替换，结束流式拼接。

---

**④ error 事件**

```json
{
  "event": "error",
  "code": 5001,
  "message": "AI 流式响应异常"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | Integer | 错误码 |
| `message` | String | 错误信息 |

**前端处理**：隐藏加载状态，显示错误提示（如"AI 回复失败，请重试"）。

#### 前端 SSE 对接示例（原生 JavaScript）

```javascript
// SSE 流式聊天示例
function streamChat(sessionId, userId, content, systemPrompt) {
  const params = new URLSearchParams({
    sessionId,
    userId: String(userId),
    content,
  });
  if (systemPrompt) {
    params.append('systemPrompt', systemPrompt);
  }

  const eventSource = new EventSource(`/chat/stream?${params.toString()}`);

  let aiContent = '';
  let aiMessageId = null;

  // 监听消息事件（默认 message 事件）
  eventSource.onmessage = (event) => {
    const data = JSON.parse(event.data);

    switch (data.event) {
      case 'start':
        // 用户消息已保存，显示用户消息 + AI 加载状态
        console.log('开始生成，用户消息ID:', data.messageId);
        showLoading(true);
        break;

      case 'message':
        // 追加增量文本
        aiContent += data.content;
        updateAIMessage(aiContent);
        break;

      case 'done':
        // 完成，用 fullContent 做最终内容
        aiContent = data.fullContent;
        aiMessageId = data.messageId;
        updateAIMessage(aiContent);
        showLoading(false);
        eventSource.close();
        break;

      case 'error':
        // 错误处理
        showError(data.message);
        showLoading(false);
        eventSource.close();
        break;
    }
  };

  eventSource.onerror = () => {
    showError('连接中断，请重试');
    showLoading(false);
    eventSource.close();
  };

  return eventSource;
}
```

#### 前端 SSE 对接示例（使用 fetch + ReadableStream，推荐用于 POST 场景/自定义 header）

`EventSource` 只支持 GET 请求且不能自定义 Header，如需更灵活控制可使用 `fetch`：

```javascript
async function streamChatFetch(sessionId, userId, content, systemPrompt) {
  const params = new URLSearchParams({ sessionId, userId: String(userId), content });
  if (systemPrompt) params.append('systemPrompt', systemPrompt);

  const response = await fetch(`/chat/stream?${params.toString()}`, {
    method: 'GET',
    headers: { 'Accept': 'text/event-stream' },
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  let aiContent = '';

  showLoading(true);

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() || ''; // 保留不完整的最后一行

    for (const line of lines) {
      if (!line.startsWith('data: ')) continue;
      const data = JSON.parse(line.slice(6));

      switch (data.event) {
        case 'start':
          // 处理开始
          break;
        case 'message':
          aiContent += data.content;
          updateAIMessage(aiContent);
          break;
        case 'done':
          aiContent = data.fullContent;
          updateAIMessage(aiContent);
          showLoading(false);
          return;
        case 'error':
          showError(data.message);
          showLoading(false);
          return;
      }
    }
  }
}
```

## 5. 推荐的前端交互流程

### 5.1 首次进入应用

```
1. 用户登录（前端自行管理 userId，目前后端无鉴权）
2. 调用 GET /chat/session/list?userId=xxx 获取会话列表
3. 左侧边栏展示会话列表（标题、更新时间）
```

### 5.2 新建会话

```
1. 用户点击"新建会话"按钮
2. 调用 POST /chat/session/create 创建会话
3. 自动进入新会话，右侧聊天区域为空
4. 会话列表刷新（或直接在前端插入新会话）
```

### 5.3 发送消息（推荐 SSE 流式）

```
1. 用户在输入框输入内容，点击发送
2. 【乐观更新】立即将用户消息 append 到聊天区域
3. 调用 GET /chat/stream?sessionId=xxx&userId=xxx&content=xxx 建立 SSE 连接
4. 收到 start 事件：显示"AI 正在思考"加载动画
5. 收到 message 事件：将 content 增量 append 到 AI 消息气泡
6. 收到 done 事件：隐藏加载动画，可用 fullContent 做最终校验，关闭连接
7. 收到 error 事件：显示错误提示，关闭连接
8. 更新会话列表的最后消息预览和更新时间
```

### 5.4 历史会话切换

```
1. 用户点击左侧会话列表中的某一项
2. 调用 GET /chat/messages?sessionId=xxx&userId=xxx 获取历史消息
3. 将消息列表按 messageIndex 排序渲染到聊天区域
4. role=user 的消息显示在右侧，role=assistant 的消息显示在左侧
```

### 5.5 重命名会话

```
1. 用户点击会话旁的"重命名"按钮，弹出输入框
2. 调用 POST /chat/session/rename 提交新标题
3. 更新左侧列表中对应会话的标题显示
```

### 5.6 删除会话

```
1. 用户点击"删除"按钮，弹出确认框
2. 调用 POST /chat/session/delete
3. 从左侧列表移除该会话
4. 如果删除的是当前会话，自动切换到其他会话或显示空状态
```

## 7. 注意事项

1. **SSE 连接管理**：用户切换会话、离开页面或发送新消息时，务必调用 `eventSource.close()` 关闭旧的 SSE 连接，避免多连接导致的消息串流问题。
2. **内容编码**：SSE 接口为 GET 请求，消息内容包含中文、空格、特殊字符（`&`、`?`、`#` 等）时必须使用 `encodeURIComponent` 编码，推荐使用 `URLSearchParams` 自动处理编码。
3. **消息长度限制**：消息内容最大 10000 字，前端应在发送前做长度校验，超出时提示用户。
4. **并发发送**：同一会话在 SSE 流未结束（未收到 `done` 或 `error`）时，不建议发送下一条消息，避免 AI 上下文错乱。建议在 AI 回复完成前禁用发送按钮。
5. **会话标题**：创建会话时标题默认为"新会话"。建议前端在用户发送第一条消息后，自动截取前 N 个字符作为标题调用重命名接口更新（可选优化）。
6. **时间格式化**：后端返回的时间为 ISO 格式字符串（`yyyy-MM-ddTHH:mm:ss`），前端需格式化为友好的展示格式（如 `"今天 10:30"`、`"昨天"`、`"MM-dd HH:mm"`）。
7. **userId 获取**：当前后端未集成鉴权，`userId` 由前端直接传入。开发阶段可硬编码一个测试用户 ID；后续接入登录鉴权后，从登录态中获取。
8. **网络异常处理**：SSE 连接可能因网络中断断开，前端需监听 `onerror` 事件并做重连或提示用户重试。
9. **历史消息分页**：当前消息列表接口一次性返回全部历史消息。若单会话消息量过大，后续需扩展分页参数。
10. **Markdown 渲染**：AI 回复内容可能包含 Markdown 格式（代码块、列表、链接等），建议前端使用 Markdown 渲染库（如 `markdown-it`、`react-markdown`、`marked`）进行渲染，并对代码块做代码高亮。
